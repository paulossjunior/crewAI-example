# Research: Dinner Pairing Crew

## R1. Python version

- **Decision**: Python 3.12 (pinned via `.python-version`), `requires-python = ">=3.12,<3.14"`.
- **Rationale**: crewai 1.15.x declares `requires-python <3.14,>=3.10`; constitution requires 3.12+.
  The machine default is 3.14, so the pin is needed for `uv` to pick a compatible interpreter.
- **Alternatives**: 3.13 (works, but 3.12 has broader wheel coverage for crewai deps).

## R2. Orchestration style in CrewAI

- **Decision**: `@CrewBase` class with `config/agents.yaml` and `config/tasks.yaml`, sequential
  process, three tasks chained via `context`.
- **Rationale**: this is the idiomatic layout generated by `crewai create crew`; prompts live in
  YAML (easy to read/edit), wiring in Python. Teaches the canonical CrewAI pattern.
- **Alternatives**: plain `Agent(...)`/`Task(...)` in Python — fewer files but less idiomatic;
  hierarchical process — needs a manager LLM, unnecessary for a fixed pipeline.

## R3. LLM configuration

- **Decision**: `crewai.LLM(model=os.getenv("OPENAI_MODEL", "gpt-4o-mini"), temperature=0)`,
  key from `OPENAI_API_KEY` loaded with `python-dotenv`. CLI checks the key before building the
  crew and exits with a clear message (FR-012).
- **Rationale**: cheap default model; temperature 0 reduces narrative variance (recommenders are
  deterministic regardless).

## R4. Content-based filtering (dishes)

- **Decision**: build one text "document" per dish from cuisine, protein, sauce, intensity and
  flavor tags; fit `TfidfVectorizer` on the catalog; transform user preference terms; rank by
  cosine similarity. Hard filter by dietary restrictions before ranking. Ties broken by dish name.
- **Rationale**: textbook content-based approach, explainable via overlapping terms (reported as
  "matched attributes").
- **Alternatives**: hand-written Jaccard over tags — simpler but loses IDF weighting, which is the
  didactic point. Embeddings — non-deterministic/external, violates constitution III.
- **Edge**: all query terms out of vocabulary or empty → zero vector → return catalog order
  (filtered) with `warning`.

## R5. Knowledge-based recommendation (wines)

- **Decision**: rules in `data/pairing_rules.json`; each rule has `when` (subset of
  `protein`, `sauce`, `intensity`) and `recommend` (`types`, `bodies`) plus `why`. A rule fires
  when all its `when` fields equal the dish's attributes. Wine score = Σ specificity
  (`len(when)`) of fired rules that endorse its type **and** body. Keep score > 0, filter by price
  tier; if empty, relax to adjacent tiers (`baixa↔média↔alta`) and set `warning` (FR-004).
  Ties → name.
- **Rationale**: explicit, auditable rules = classic knowledge-based recommender; specificity
  weighting rewards more precise rules.
- **Alternatives**: constraint solver / ontology — overkill for toy.

## R6. Collaborative filtering (restaurants)

- **Decision**: user-based CF with mean-centered cosine similarity (≈ Pearson) on a user×restaurant
  rating matrix (numpy, 0 = not rated). Prediction for item *i*:
  `r̂(u,i) = μ_u + Σ_v sim(u,v)·(r_v,i − μ_v) / Σ_v |sim(u,v)|` over the top-k (k=3) neighbors
  with sim > 0 who rated *i*. Candidates = restaurants matching cuisine + city, not rated by *u*.
  Fallback (unknown user / no history / no neighbor rated the item) → item mean rating
  ("popularity") with `warning`. No candidates in city → same cuisine in any city, with warning.
  Predictions clipped to [1, 5]; ties → name.
- **Rationale**: canonical CF formulation; mean-centering handles harsh vs lenient raters.
- **Alternatives**: item-based CF or matrix factorization — fine, but user-based is easiest to
  explain ("people like you liked…").

## R7. Tool ↔ agent contract

- **Decision**: each tool is a `crewai.tools.BaseTool` subclass with a pydantic `args_schema`,
  returning a JSON string with `technique`, `items[]` (each with `score` and `explanation`) and
  optional `warning`. Recommenders are loaded once from `data/`.
- **Rationale**: JSON keeps LLM grounded on exact item names (FR-011) and makes tools testable.

## R8. Testing

- **Decision**: pytest unit tests per recommender against real toy data; tool tests call `_run`
  directly; crew smoke test builds the crew with a dummy key (no `kickoff`). No network.
